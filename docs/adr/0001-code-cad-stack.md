# ADR-0001 — コード CAD のスタックを build123d + ocp_viewer + watchfiles に定める

- 状態: 採用
- 日付: 2026-10-16
- 根拠の調査: [コード CAD スタックの比較(2026-10)](../research/code-cad-stacks-2026-10.md)

## 背景

小さな機能部品と電子工作の筐体を、公共の工房の FDM 機で刷る試行錯誤を、できるだけ短い周期で回したい。設計は Python のスクリプトで書く。刷る前に形を見て、有効性・干渉・造形範囲を機械で確かめ、スライサーへは 3MF で渡す。

評価は、表現不可能性(不正な状態を作れなくする)、還元性(より安い手段で足りないときだけ残す)、先進性(上 2 つが同点のときの同順位破り)の順で行う。書き直しの作業量や、すでに使っているという経緯は理由にしない。戻せないものは、この選択には無い。

## 決定

1. **形状の記述は build123d 0.13.0**。`pyproject.toml` では完全一致で pin する(`build123d==0.13.0`)。Python は 3.13 に固定する。
2. **ビューアは ocp_viewer**。常駐させ、スクリプトは `show()` で送る。
3. **保存時の再実行は watchfiles**。uv の dev 依存として持ち、`lab watch` が使う。
4. **書き出しは 3MF(スライサー向け)と STEP(CAD 間の交換向け)**。3MF は build123d の `Mesher` で書き、許容差は引数で受ける。
5. **AI 補助は検査の CLI(`lab check`)に限り**、MCP サーバは足さない。

## 評価

### 1. build123d(対抗馬: CadQuery、OpenSCAD + Manifold)

- 本命は、調査の前から決まっていた(憧れ駆動)。現職でもあるため、白紙から選ぶ評価をやり直した。
- 表現不可能性: 筐体のはめ合いにはフィレットと厳密な寸法が要るので、B-rep のカーネルを持つ CadQuery と build123d が残る。メッシュだけの OpenSCAD + Manifold は、STEP と真のフィレットが無いため落ちる。完全一致の pin で、意図しない版が入る状態を作れなくする。
- 還元性: CadQuery と build123d は同じ OCCT の上にあり、書き出し形式も同じ。差は API と kernel の版で、build123d 0.13.0 は OCP 8.0、CadQuery 2.8.0 は OCP 7.9(調査報告)。この 2 つの間では、決定的な差を見つけられなかった。build123d は現職で、乗り換えてもどの軸も良くならないため、維持する。
- 外した候補は、Zoo + KCL(クラウド必須で 3MF が書き出し形式に無い)、NeoSCAD(開始 3 週間で若すぎる)、replicad / JSCAD(JS 系)、PythonSCAD / SolidPython2 / FreeCAD スクリプト(利用者の少なさ・API の重さ)。**これらは分析ではなく感触で外した**。Fornjot は 2026-06 に開発が終了した。
- 先進性: build123d 0.13.0 は 2026-09-21 に出た最新版で、OCP 8.0 に追従している。採用の理由は先進性ではない(上の 2 軸で決まった)。

### 2. ocp_viewer(対抗馬: yacv)

- ビューアを常駐させ、スクリプトが形状を送るだけにできる。yacv は実行のたびにサーバを作り直す。CAD の厳密値(距離・角度・半径・体積)で測れる点も、部品の寸法確認に効く(還元性)。
- yacv は、build123d が書いた GLB の描画(#264)と、再実行で `clear()` が効かない(#257)という既知の問題を持つ。
- 実機で、描画・保存での自動更新(5 秒以内)を確かめた。ネットワークを切った表示とクリッピングの操作は未確認。

### 3. watchfiles(対抗馬: watchexec)

- watchexec は、どのホストの home-manager にも入っていない。watchfiles は `uv.lock` に pin され、clone して `uv sync` すれば、どのホストでも同じ版が入る(単一の正本)。
- entr は、新しいファイルを拾いにくいので外した。**感触で外した**。

### 4. 3MF と STEP

- 3MF は、スライサーがそのまま開ける形状のプロジェクト。Bambu Studio 2.8.2.61 の CLI で、書き出した 3MF のスライスが通ることを確かめた(機種・フィラメントのプリセットなしでの確認)。
- STEP は、CAD 間の交換と、形状そのものの保存のために残す。

### 5. AI 補助

- 公開ベンチでは `build123d-mcp` で妥当率が上がったという報告がある。ただし、有効性・寸法・干渉の検査は、`lab check` として CLI に持てば、人も Claude も同じ判定を Bash から呼べる。MCP の追加は、より安い手段で担えない仕事をまだしていないので、足さない。

## 結果

- build123d を上げるときは、API の変更を読み、`lab check --all` と `pytest` が通ることを確かめてから pin を上げる。
- ocp_viewer は 2026-08 に分離された新しいパッケージで、maintainer は 1 人。ビューアは差し替えやすい層(`ocp_viewer` を呼ぶのは `lab show` と `lab viewer` の 2 箇所だけ)に閉じ込めてある。
